perf(fable): 이미지 생성 4장 병렬 처리 — 25분 → 25초

## 문제
2026-10-08 첫 자동 발행 run이25분 걸렸다.
원인은 Pollinations 이미지 10장을 **순차 호출**하면서 402 쿼터로
매번 백오프를 기다린 것:
- 1장당 최대 4회 시도 (10/30/60/90초 백오프)
- 10장 × 실패 = 수십 분
- 게다가 GitHub Actions 는 매번 새 IP 라 쿼터가 이어져
  백오프로 회복되지 않는다 (사실상 무의미)

## 해결: 4장씩 병렬 + 짧은 백오프
1. `gen_images()` → `_fetch_one()` 추출, ThreadPoolExecutor(max_workers=4)
   로 4장씩 동시 요청.
2. 백오프 (10,30,60,90) → (5,20) 로 축소.
   쿼터가 안 풀리면 빨리 로컬 폴백으로 넘어가는 게 낫다.
   폴백 이미지는 다음 실행에 캐시로 재사용된다.
3. 순서 보장 — results 는 scene1..scene10 순으로 재배열.

## 효과 (실측)
- 10장 처리: **25분 → 24.5초** (네트워크 402 상황 기준)
- 순서·파일명 정합성 확인 완료 (scene1.jpg ~ scene10.jpg)

## 참고
- 폴백 이미지는 PIL 파스텔 그라디언트라 품질이 낮지만,
  파이프라인이 중단되지 않는 것이 우선.
- 쿼터가 회복되면 다음 실행에서 실제 이미지로 교체된다.
- `scene{i}.mono` 마커 덕분에 후처리가 중복 적용되지 않는다.
